# إصلاح ADB: من 127.0.0.1 إلى IP:5556 — X5M

## لماذا لم يكن الاتصال يعمل؟
- زر USB ADB السابق كان اختصاراً لإعدادات المطوّر فقط، وليس عميل بروتوكول ADB.
- `127.0.0.1` عنوان loopback المحلي للجهاز الذي ينفذ البرنامج، وليس عنوان الريسيفر من هاتف آخر.
- تفعيل **USB debugging** وحده لا يجعل `adbd` يستمع على `5556/TCP`.
- إذا كان جهازك هو `192.168.0.214` حسب اختبار ADB السابق، استعمل `192.168.0.214:5556` بعد تأكيد العنوان الحالي.

## ما نُفذ
- صفحة **إعدادات X5M → ADB عبر IP:5556** فيها إدخال IP أو DNS اسم محلي + المنفذ، زر «اتصال وفحص تفويض»، وحالة حقيقية (مغلق/مفتوح بلا بروتوكول/غير مخوّل/مخوّل).
- عميل ADB TCP legacy يولد مفتاح RSA 2048 غير قابل للتصدير ويخزنه في AndroidKeyStore.
- بعد تأكيد ADB CNXN، يُرسل **فقط** `shell:id` للتحقق من اتصال المستخدم المخوّل، ويغلق اتصال الاختبار. ليس مساراً لتنفيذ أوامر Shell عشوائية أو لاختراق حماية Aurum.
- لا يخرج إلى IP عام: يحل DNS فقط إلى عنوان خاص أو loopback.
- اختيار «فحص تلقائياً عند بدء اللانشر» اختياري، افتراضياً متوقف. تكرار الطلبات محدود مرة كل دقيقتين أثناء عودة اللانشر.
- زر اللانشر `ADB IP ✓` يظهر عندما نملك تحقق تفويض خلال آخر 5 دقائق فقط؛ زر `ADB ON` يعني أن إعداد Android مفعّل ولا يعني أن اتصال IP موثوق.
- `adb_ip_status`، `adb_ip_detail`، `adb_ip_verified_target`، ووقت آخر فحص محفوظة لغرض التشخيص.

## تهيئة 5556 للمستخدم المصرح — من كمبيوتر/هاتف يملك ADB يعمل مع كابل USB
```sh
adb devices -l
adb tcpip 5556
adb connect 192.168.0.214:5556
adb devices -l
```
- يجب أن تستبدل IP بالعنوان الحقيقي للرسيفر؛ ربما يتغير بعد إعادة تشغيل الراوتر.
- `adb tcpip 5556` يحتاج اتصال ADB مخوّلاً مسبقاً، ولا يُنفّذ من التطبيق بدون إذن.
- إذا ظهر مربع «Allow USB debugging?» على شاشة X5M، أكّد بصمة الجهاز المضيف الذي تثق به فقط.
- المنافذ المفتوحة على الشبكة المحلية فقط؛ لا تعمل Port Forwarding إلى الإنترنت.
- لا حاجة لتفعيل OEM unlocking.

## DNS-over-TLS ليس ADB TLS
- Android Private DNS/DoT يحمي استعلامات DNS، لكنه لا يشفّر البايتات على `IP:5556`.
- عميل IRAQhub هنا **legacy ADB TCP**. لا يقبل أن يخدع المستخدم عبر ادعاء TLS؛ إن أرسل adbd رسالة `A_STLS`، يظهر `ADB_TLS_REQUIRED` ويتوقف بلا downgrade.
- ADB TLS الحديث على Android مع Wireless debugging يحتاج pairing منفصلاً ومنفذ اتصال معلناً مختلفاً غالباً عن 5556. الاقتران نفسه **غير مطبق** داخل هذه النسخة؛ يمكن استخدام `adb pair` و`adb connect` من محطة ADB خارجية مخوّلة.
- DNS المحلي قد يحتاج Private DNS مفعلاً من إعدادات Android، لكن لا يمكن استخدامه لتجاوز صلاحيات shell.

## حدود أمان ووظيفة
- التطبيق يختبر الاتصال ويغلق Socket بعده، **ولا يُنشئ جلسة shell دائمة**. وصف النتيجة «مخوّل وقت الاختبار» وليس «قناة دائمة للوغوات».
- ليس Root ولا يزيل الحاجة إلى Accessibility/Overlay في ميزات أخرى.
- لا يعني التحقق من ADB وجود شعارات أكثر؛ لاستيراد لوغوات استخدم حزمة ZIP الآمنة المرتبطة بهوية DVB، أو جلبها عبر مصادر الصور المرخصة.
- لا يكتب إلى /dev/vfd أو /sys ولا يغيّر معلمات adbd.
- يلزم تحقق فعلي من AndroidKeyStore وتفاعل نافذة RSA على Firmware X5M.

## حالات الاختبار
| الحالة | المتوقع |
|---|---|
| `192.168.x.x:5556` ولا يوجد مستمع | ADB_PORT_CLOSED |
| منفذ TCP مفتوح وليس adbd | ADB_BAD_PROTOCOL / ADB_CONNECTION_ERROR |
| أول اتصال بمفتاح جديد | شاشة تفويض RSA تظهر على X5M |
| موافقة المستخدم + CNXN + shell:id | ADB_AUTHORIZED |
| رفض التفويض | ADB_WAITING_FOR_AUTH / ADB_UNAUTHORIZED |
| منفذ ADB TLS الحديث | ADB_TLS_REQUIRED، دون انتقال إلى plaintext |
| عنوان إنترنت عام | ADB_RESTRICTED |
| Private DNS يعمل | لا تتغير حماية ADB TCP نفسه |

**لا تعتبر PR مستقراً حتى يُختبر التحقق من تفويض ADB على X5M.**
